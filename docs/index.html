The problem

The expensive knowledge is the model in the engineer's head.

A senior engineer's most valuable knowledge isn't the code in front of them — a model can read that. It's the causal model in their head: what breaks if you touch this, which service is fragile under load, which config flag silently couples two teams, which "safe" change took down checkout last spring.

That model is assembled from years of heterogeneous signals and deepens with every outage. Today's AI tools are stateless decoders — they re-derive your system from text every prompt, act, and forget. Retrieval helps them look things up; it does not fold an incident's lesson into the next prediction. That is an architectural gap, not a prompt-length one.

A graph is a map (what connects to what). A world model is a predictor of consequences — and it can be wrong, checked against reality, and corrected. Four behaviors separate them:
Interventional

Answers do(change) with forward-propagated probabilities — not "what's adjacent." Reachability is a strictly weaker query.

State-conditioned

The same change has a different blast radius on a healthy vs. a saturated system. A static graph cannot express that.

Self-correcting

A surprise — something it judged safe that broke — teaches it a coupling the graph never had. It deepens.

Calibrated

Every edge is a probability with an uncertainty — and we measure whether "70%" actually means 70%.

"It's just a graph" is literally one of the baselines:
topology reachability (BFS)0.083
full model, learning off (ablation)0.083
full world model (learning on)0.013
The graph alone gets you 0.083. The drop to 0.013 is produced by what the model does with it — the learning, the state-conditioning, the calibration — not the box-and-arrow diagram.
What it is

A structured causal world model — not a neural one.

It is not a world model in the neural-latent-dynamics sense. It's an explicit typed graph with Bayesian, outcome-earned weights — the way a physics simulator with known equations and estimated parameters is still a model of the world. What it is not is a knowledge graph you query for neighbors.

Every edge carries provenance — was this structure given to us, or learned from an outcome? — and a Beta-distributed weight: a confidence and an uncertainty. So the model knows what it knows, and how well.

The core principle
Signals propose.
Outcomes decide.

Structural & decision signals — code, topology, ADRs, ownership, postmortems — may propose nodes and edges.

Only outcome signals — incidents, fault injections, SLO breaches — grant or revoke causal weight. The model believes what the running system demonstrates, not what a document asserts.

The experiment — falsifiable & pre-registered

One hidden coupling. Ground truth measured, not authored.

System under test: Online Boutique (12 microservices) deployed to an isolated namespace on a real EKS cluster, with a load generator driving live browse/cart/checkout traffic.

We injected a hidden latency coupling — EXTRA_LATENCY=3s on productcatalogservice — and read the per-service p95 from distributed traces (Tempo) before vs. after. The fault was then reverted. The claim, win conditions, and frozen scenario hash were committed before any scoring.

RAG-Opus is handed the incident history. Confidence is agreement frequency over 5 samples — not a verbalized "I'm 80% sure."

Two honesty rules — enforced on every result
Rule 1

Headline metrics live only on the HIDDEN stratum — couplings the model was never given and had to learn. Scoring on the GIVEN structure would be grading it on its own cheat sheet.

Rule 2

The taught node is genuinely parsed, never synthetic. EXTRA_LATENCY is a real runtime knob of the service; the harness declares it in its OFF state before parsing, so the parser emits an inert, unconnected config node — the downstream blast is the hidden edge the engine must discover.

Reading the single-pass result

Even Opus with retrieval over the exact incident (0.027) does not match the deepened graph (0.013); stateless Opus (0.127) is far behind. Honest limits — what a skeptic should still push on

The honesty is the brand. Here's where this is thin.

k = 1
One genuine non-topological coupling

The multi-pass depth is on a single latency coupling, so the bootstrapped CI is degenerate at k=1. Breadth needs more independent hidden edges.

fault surface
Online Boutique is thin

EXTRA_LATENCY exists only on productcatalog; CPU-limit squeezes don't bite at light load, and collapse to "all callers" (topological) under heavy load.

coverage
Partial trace coverage

ad/cart/shipping didn't surface under their own service name. They sit off the productcatalog call path — not in the blast regardless — but a fuller study would instrument them.

abstention
No risk–coverage yet

Calibration is shown via the deepening curve and reliability plots, not yet an abstain / ask-a-human policy. Beta variance makes this natural — it's on the roadmap.

scoring
Binary label vs. per-window

The collapsed binary label discards checkout's graded truth; the per-window score rewards calibration. Both are reported, not cherry-picked.

persistence
Not yet checkpointed

The model is rebuilt each run from manifests + the incident log; durable memory lives in the incident log. Load-and-continue is storage, on the roadmap.

Extensible architecture — where this goes

Built to grow without the core changing.

Clean extension points — today
zero core change

New coupling = parse the knob as a config node + measure ground truth. propagate and learn are coupling-agnostic — no engine code changes.

protocol

New LLM / provider = implement LLMClient.complete via make_live_client. Anthropic, OpenAI, or the Claude Code CLI today.

dials

Ablation dials — learning_enabled, learn_call_edges — make every causal claim falsifiable by flipping a flag.

one bus

More signals — decisions, ownership, docs — plug into the same propose / decide interface. The substrate itself is swappable.
